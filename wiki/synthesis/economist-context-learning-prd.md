# PRD｜Economist Reader：兴趣驱动的上下文英语学习

Economist Reader 帮助英语学习者持续阅读自己关心的《经济学人》议题，把原文中的查词、翻译、划线和思考转成有来源的拼写练习，再用同主题的新文章检验理解与词汇迁移。

版本：v0.2，产品提案，2026-11-09。根据用户补充，将第三份知识库素材正式用于读书笔记与学习笔记设计。本文供产品、设计和开发评审；核心交互已有本地原型，完整产品需求与学习效果尚待实现、验证。

本地实现与演示边界：[旁读 Margin MVP 原型说明](../../prototype/README.md)。

## 1. 需求依据与边界

**用户明确要求**：阅读《经济学人》；学习单词拼写；文章划重点；选词、选句翻译；按兴趣分类；推荐感兴趣但漏读的文章；在真实 context 中增加词汇量，并持续接触感兴趣领域的思想、提升英语能力；覆盖 Wiki 两份产品素材的能力。

**来源解释**：阅读与拼写能力依据 Infinite Reader、TypeWords 两份产品素材；根据用户补充，读书笔记与学习笔记正式参考第三份 `sources/2026-11-09-wechat-ai-knowledge-base/`：两个库、一手/加工/索引三层、AI 加工经人签核。具体交互和权限实现由本 PRD 提案，不改变仓库自身维护规约。

| 标记 | 含义 | 本文用法 |
|---|---|---|
| U | 用户明确需求 | 上述原始目标 |
| S1 | Infinite Reader 素材 | 阅读体验、行内批注、标签、伴读、导图、地图；主动提问和游戏化为原作者路线图[^src-reader] |
| S2 | TypeWords 素材 | 打字输出、词条信息、词库、自带文章导入、学习统计；视频未逐一展示四种模式[^src-typewords] |
| S3 | 知识库文章 | 我的库 / AI 的库；一手层只有人写、加工层 AI 写人签、索引层自动；属于作者主张，本产品据此设计笔记[^src-wiki] |
| D | 本 PRD 的设计提案 | 推荐算法、复习规则、优先级、指标和交互，不代表素材中已有实现 |

除明确归因的素材事实外，下文均为 D。目标用户水平、学习效果、推荐偏好、时间预算和上线指标均为假设 **（待验证）**。不把“效率翻倍”写成产品承诺，也不把本文设计的四种练习模式称为 TypeWords 的原有四种模式。

## 2. 产品定位与目标用户

**定位**：面向希望通过有思想内容的英语阅读获得长期进步的学习者，提供“兴趣阅读 + 语境理解 + 主动拼写 + 跨文章再遇见”的学习工作台。

首批用户假设为能读简单英文、面对《经济学人》仍常被生词和长句打断的大学生、研究生及自学者，英语水平暂按 B1–C1 覆盖，重点验证 B2 左右用户。分级只用于选择辅助强度，不向未测评用户直接赋予正式等级。

| 场景 | 当前困难（需求推导，待访谈验证） | 需要完成的任务 |
|---|---|---|
| 对 AI、经济、国际关系等主题有兴趣 | 选文多，难判断哪篇值得读 | 找到今天能读完且值得读的文章 |
| 读到长句或陌生表达 | 查词跳出正文，回来丢失上下文 | 理解该处词义、句子结构和论证作用 |
| 读完一篇文章 | 认识但拼不出，笔记难再用 | 记住与自己相关的表达，并能主动写出 |
| 连续关注某个主题 | 不知道漏了哪些关键背景 | 补读旧文、比较不同观点、追踪发展 |

核心任务陈述：**当我阅读关心议题的英文文章时，我希望及时理解难点、留下自己的判断，并在后续练习和阅读中再次使用这些表达，让英语提升成为持续阅读的结果。**

首版服务个人自学。班级管理、教师布置作业、考试课程和多人协作不进入首版；它们作为可能的后续场景保留。

## 3. 产品目标与体验原则

1. **兴趣推动阅读**：发现页优先解释文章与用户关心的问题有何关联。
2. **帮助贴着正文**：查词、翻译、笔记、伴读均可在原位置完成并关闭返回。
3. **每个学习项都有语境**：词汇默认保留来源句、文章和该处义项，能一键回跳。
4. **识别与输出分开记录**：看懂、抄对、无提示拼对、延迟回忆分别计分。
5. **循序增加自主性**：用户可先看提示，再尝试解释、拼写和复述；辅助随用户选择调整。
6. **保护人的判断**：AI 提议不能悄悄成为“我的笔记”或“我的观点”。

长期目标是更多独立阅读、更好的词汇保持和更丰富的主题理解；首版先验证这条闭环是否有人持续使用，不预设效果已经成立。

## 4. 核心使用流程

### 4.1 首次使用

选择 3–5 个兴趣主题（可跳过）→ 自报阅读信心与每日可用时间 → 选择一篇可访问文章或导入自己的正文 → 阅读、选词解释、划线 → 将少量生词加入练习 → 完成一次无提示拼写 → 获得下一篇同主题文章及推荐理由。

兴趣选择不足时提供可浏览的主题目录；不强制做长测评。演示采用自有或可使用的短文，并清楚标注来源。

### 4.2 日常闭环

打开“今天” → 继续上次阅读或选择新文 → 正文中即时理解与记录 → 结束后自主选词练习 → 在到期日做短时复习 → 阅读同主题的另一篇文章，在新句子中再次遇见学过的表达。

建议默认每日 15–25 分钟、每篇选 3–8 个重点词，为可调整的产品默认值 **（待验证）**。阅读不以完成复习为解锁条件。

### 4.3 贯穿示例

用户关注“AI 对就业的影响”，读到包含 `displacement` 的句子。点词后看到该处义项、音标和原句解释，标记一个关于就业结构的论点，并写下自己的疑问。随后将该词加入学习，在原句挖空题中输入正确词形；下一次不显示英文答案进行拼写。系统从可用文章库中推荐一篇讨论工资变化的未读文章，说明它补充了当前议题的另一个角度。

以上是虚构交互示例，不对应真实《经济学人》文章或引文。

## 6. 功能需求与验收

优先级定义：**P0 = 首版上线闭环必需；P1 = 闭环验证后的增强；P2 = 完整能力路线图。** 本文“覆盖来源能力”指全部列入产品范围并标记阶段，不等于全部塞入 MVP。

### 6.1 内容进入与阅读

| ID / 优先级 | 需求 | 验收标准 |
|---|---|---|
| C01 / P0 | 手动粘贴、TXT/Markdown 导入正文；附标题、来源 URL、发布时间（允许未知） | 导入后预览段落并确认；空文、乱码、缺标题有提示；未知日期不自动编造 |
| C02 / P0 | 内容目录支持只有元数据的文章与已有正文的文章 | 无正文条目可打开来源；只有元数据时不提供全文翻译、全文问答或伪造词汇覆盖率 |
| C03 / P0 | 阅读器提供字体字号、行宽、浅深色、目录/段落定位、进度和断点续读 | 重开文章恢复位置；调整字号后仍能定位笔记；用户能主动标记读完或重新打开 |
| C04 / P1 | EPUB、JSON、XLSX 导入；JSON/XLSX 给出模板、字段映射和逐条错误报告 | 正文、词条和来源字段不混用；失败项可修复重导；重复内容可选择合并或另存 |
| C05 / P1 | 已授权或允许接入的来源链接解析 | 解析失败可手动导入；保留出处；遇到访问受限时跳转原站并说明正文不可用 |

首版只依赖用户有权使用的内容与已确定可用的内容元数据；不假定产品已经拥有《经济学人》全文供给。是否可持续获得历史目录、正文和更新源，是进入完整推荐功能前必须解决的产品依赖；本稿不对具体接入许可作判断。

### 6.2 选词、选句与语境理解

| ID / 优先级 | 需求 | 验收标准 |
|---|---|---|
| R01 / P0 | 单词卡显示原词、词元、词性、该处义项、音标、原句和文章入口 | 多义词优先解释当前句义；专名、缩写、习语无法确定时明确提示；可展开其他义项 |
| R02 / P0 | 选句翻译与长句拆解 | 同屏保留英文；区分译文、语法说明和推断；跨段选区保持顺序；失败保留选区可重试 |
| R03 / P0 | 选词/选句菜单：解释、翻译、高亮、笔记、加入学习、问伴读 | 每个入口仅作用于当前选区；操作后仍能返回原阅读位置；加入学习前可编辑义项 |
| R04 / P1 | 单词与句子发音、短语、近义词及区别 | 播放可停，音频不可用有提示；近义词说明适用差异；原文例句与生成例句分开标记 |
| R05 / P1 | 可调辅助强度与关键搭配卡 | 用户自行选择简短释义、句子解释或深度拆解；短语作为整体加入学习 |

默认以选区及必要邻近段落提供解释，全文翻译后续按需提供。翻译结果允许反馈“意思不对”，更正后保留版本与来源。

### 6.3 划线、笔记和兴趣分类

| ID / 优先级 | 需求 | 验收标准 |
|---|---|---|
| N01 / P0 | 多色高亮、行内批注、标签；支持编辑、删除、撤销 | 刷新后保留；每条笔记可回跳对应原句；划线与笔记可分别删除 |
| N02 / P0 | 标签支持用户主题，如 #AI就业、#论据、#不同意 | 同标签可聚合跨文章内容；可搜索、合并与改名；改名保留引用关系 |
| N03 / P0 | AI 建议主题分类，用户确认后成为个人主题 | 区分“AI 建议标签”与“我的标签”；建议不自动改写既有分类；用户可批量确认 |
| N04 / P0 | 我的笔记、AI 草稿分别存储和展示 | AI 不能覆盖用户笔记；采纳或编辑保存后保留 AI 辅助来源标记；导出也保留作者类型 |
| N05 / P1 | 主题页聚合文章、观点、笔记、词汇和未解决问题 | 所有观点有原句入口；明确标识原作者观点、用户观点和 AI 归纳 |
| N06 / P2 | 手写风格字体、批注配色与阅读外观个性化 | 装饰不影响正文、选区和可访问性；可恢复默认样式 |
| N07 / P0 | AI 整理以候选草稿进入待确认区，签核后才可进入我的库 | 用户逐条采纳、修改后采纳、拒绝或暂存；无默认勾选和默认整批采纳；未操作不入库 |
| N08 / P0 | 一手笔记、AI 草稿、已签核版本与人工改动可追溯 | 已签核内容被 AI 重整时产生新候选，不覆盖旧版；用户可查看差异、撤回采纳；原始记录保留版本 |
| N09 / P0 | 自动索引、关联和回顾可以后台更新 | 始终标明自动生成；能回跳笔记与原文；索引中的推断不写回个人结论或权威标签 |
| N10 / P0 | 读书笔记与语言学习笔记均可快速记录 | 半句、疑问或错法也能保存；结构模板可选；AI 补写必须进入加工层，不能填成用户原话 |

长按、双击和拖选需兼顾移动端与桌面。保存使用原文版本、段落/句子标识、选中文本及前后文锚定；原文更新导致无法定位时显示“需要重新定位”，不得静默贴到错误句子。

#### 6.3.1 笔记系统：两个库、三种职责

采用 S3 的分工：**记录和判断留给学习者，归类、关联与整理交给 AI；进入个人判断库的加工内容，由用户签核。**[^src-wiki] 这里的一手层指学习者自己的观察，文章原文仍是独立、可追溯的素材层，两者不混同。

| 区域 / 职责 | 存什么 | 谁能写 | 用户看到什么 |
|---|---|---|---|
| 我的库 / 一手层 | 我的理解、怀疑、立场、错因、尝试写出的英语、当时没想清楚的话 | 用户创建和修改；系统代表用户保存，AI 无写入权限 | “我写的”，保留时间、原文锚点和修改历史 |
| AI 工作区 / 加工层 | 摘要、改写建议、关联、词义解释、主题综合、复习小结草稿 | AI 生成候选；用户签核指定版本后，应用才写入我的库中的“已确认整理” | “AI 草稿”或“我已确认 · AI 辅助”，不冒充原始记录 |
| 自动索引 / 索引层 | 检索摘要、主题导航、关联图、按时间生成的回顾和学习统计 | AI/系统自动维护，不逐条签核 | “自动生成”，只负责找内容和发现线索 |

**我的库内部区分“原始笔记”和“已确认整理”**：签核不会把加工结果改标为“我写的”，也不会删除当时的犹豫。AI 可以在用户允许的范围内读取这两类内容，不能直接新增、改写、删除它们。真正的入库操作由应用在验证用户明确操作后执行；不能只靠提示词约束模型。

**读书笔记可选模板**：引用原句 → 我理解作者在说什么 → 我同意/不同意/还不确定什么 → 原因或联想到的问题。可只写其中一句；收藏和高亮本身不代表已经理解、同意或形成了观点。

**学习笔记可选模板**：原句与目标表达 → 我原先理解/拼写成什么 → 正确或更合适的用法 → 我自己的例句/仍然不明白的地方。练习系统自动记录的错误是学习事件；“我为什么错”只有用户亲写或明确确认后才能成为个人错因结论。

例如，用户输入“我不确定这个词在这里是否带贬义”，AI 可以给出语境分析，但不能将个人笔记改成“我已掌握该词的贬义用法”。用户可接受解释、保留疑问或记录不同意见。此例是产品交互示例。

#### 6.3.2 从记录到签核的具体流程

1. **先记下来**：划线后点“记我的想法”，直接保存原话；不要求先选主题或补全模板。翻译、AI 对话和导图默认留在 AI 工作区或缓存，不自动变成个人笔记。
2. **按需整理**：用户选择一条或一组笔记，点击“请 AI 整理”；显示本次可读取的范围，AI 生成有引用的候选结论和关联。后台可以更新索引，不持续向用户堆积待签核长文。
3. **对照审阅**：同时展示原始笔记、AI 候选、来源句和改动；新增论断、语气加强、推断及观点冲突需突出显示。
4. **明确签核**：每个独立判断提供“这是我的意思，采纳”“修改后采纳”“拒绝”“稍后”。可以接受其中一条、拒绝另一条；浏览、关闭、读完文章或勾选兴趣均不构成签核。
5. **写入与回溯**：记录候选版本、用户、确认时间及人工修改差异，再存为已确认整理。用户可回到最初原话、撤回采纳或修订自己的结论；撤回的内容退出当前个人结论视图，保留历史。

状态流转为：`AI 草稿 → 待确认 → 采纳 / 修改后采纳 / 拒绝 / 暂存`；已采纳项可撤回。AI 重生成产生新版本并重新待确认；签核绑定具体版本，候选或其依据变化时，旧确认不能套用到新文本。签核属于产品中的学习行为，不是要求用户逐条审批本仓库 PRD 的写入。

#### 6.3.3 思考归属、冲突与回顾

- **保留分歧**：原作者、用户和 AI 的不同判断并列展示；不同时间的用户观点相冲突时提示“可能变化”，由用户决定是否更新，AI 不自动统一口径。
- **不自动升级掌握程度**：用户确认一段词义说明，只表示认同该解释；只有独立拼写、延迟回忆和新语境任务才能产生相应表现记录。
- **回顾支持行动**：自动回顾优先找出未解决的问题、改变过的判断和仍易错的表达，并提供回原文、补读和再练入口；默认不把未确认草稿混入“我的观点”。
- **减少签核负担**：按需生成、短条呈现、支持暂存和拒绝；首版不设签核数量打卡，不以笔记总量当学习成绩。“三十秒签核”只是素材作者自述，不作为本产品时限承诺。
- **自动摘要的边界**：索引层可自动总结“你记录过哪些问题”，但不得把尚未表达的结论写为“你认为”；如用户要把自动回顾保存成个人学习总结，仍走加工层签核。

额外验收场景：模型尝试直接写个人库应被权限层拒绝；用户只采纳两条候选中的一条时另一条不入库；签核前候选版本变化时要求重新审阅；拒绝和撤回后的候选不出现在“我的观点”结果中；人工与 AI 文字差异在导出后仍可辨认。

### 6.4 带引用的 AI 伴读

| ID / 优先级 | 需求 | 验收标准 |
|---|---|---|
| A01 / P0 | 针对选句或当前文章问答：解释、论点、证据、反驳关系 | 关于原文的判断附可点击段落引用；找不到证据时说明原文不足；引用点击能定位 |
| A02 / P0 | 输出分清原文信息、模型解释与额外背景 | 未检索核实的背景标为“AI 补充，待核对”；不虚构来源；原文无答案时不装作有答案 |
| A03 / P1 | 文章论证导图：主张、证据、转折、结论 | 节点可展开/折叠、回到原段；按文章版本缓存；重新生成不覆盖用户笔记 |
| A04 / P1 | 可选的阅读挑战：概括观点、找论据、比较观点、用目标词复述 | 在自然段落结束或读后出现；可跳过、调频、关闭；反馈引用原文并允许不同立场 |
| A05 / P2 | 跨文章伴读与主题综合 | 标出各篇支持/冲突关系；摘要存为 AI 草稿；用户决定是否采纳为自己的判断 |

伴读对正文内命令式内容仅作文章内容处理；不得据此改变系统行为、读取其他用户数据或发起未授权外部操作。

### 6.5 从文章到拼写与复习

**学习单位**：词元 + 当前义项 + 至少一次原文出现。相同词元的新义项单独关联；同义项在多篇文章出现时增加语境记录，不重复创建孤立词卡。短语保留整体，词形与词元同时存储。

| ID / 优先级 | 需求 | 验收标准 |
|---|---|---|
| V01 / P0 | 查词后可手动加入学习；读后推荐少量词供勾选 | 不因每次点词自动塞满词库；推荐显示原因；同义项去重；可排除已知词与专名 |
| V02 / P0 | 每张卡带来源文章、原句、该处义项、目标词形 | 任意练习可回看上下文；回看后该题标为“已提示”；找不到来源时提示修复 |
| V03 / P0 | 看词拼写与原句挖空拼写 | 前者标为熟悉练习；后者遮住目标词并按句子所需词形判定；结果不混算 |
| V04 / P0 | 根据中文义项及语境提示主动拼写，提交后反馈 | 正确提交前不显示英文答案；提示、揭示、回看、首次错误分别记录；可查看错字位置 |
| V05 / P1 | 听音拼写、短语及文章片段打字 | 音频缺失可跳过；原文临摹不计为独立回忆；记录字符错误和词形错误 |
| V06 / P0 | 错词队列、到期复习、暂停/移出学习 | 默认按 1/3/7/14/30 天安排无提示成功后的递增复习；失败进入本次末尾重试并次日到期；提示成功不升级间隔 |
| V07 / P0 | 认识度、拼写与语境表现分别展示 | 今日答对不直接显示“永久掌握”；至少显示最近无提示结果、延迟复习记录和来源语境 |
| V08 / P1 | 自建词库、可用的考试词库、JSON/XLSX 词条导入 | 词库注明来源；外部词条标记“尚无阅读语境”，在文章出现后关联原句；有重复与错误报告 |

上述四种模式（看词、原句挖空、义项提示、听音）为本产品自行定义；S2 只证明其视频提及“四种模式”，不能证明与本设计一致。复习间隔是首版可解释的默认规则，学习收益 **（待验证）**，后续依据真实表现调整。

**拼写判定**：忽略首尾空格；普通词大小写默认不敏感，专名可严格；原句题必须符合原句词形，不把词元直接当作正确答案。英美拼写、连字符与撇号变体以显式可接受答案表判定，用户可申诉；粘贴或揭示答案不计入无提示成绩。使用中文输入法合成期间不逐字符判错。

**在新 context 中使用**：P0 通过人工策展的主题候选文章提供再次阅读，只有已有正文能定位到目标词时才显示“这篇含你学过的词”；P1 增加未见句的义项辨析、目标词造句和短复述。AI 对造句给建议，学习报告不把模型打分直接当作已证实的能力提升。

### 6.6 兴趣推荐与漏读发现

推荐同时回答：**为什么我会关心？它补充了什么？现在读是否合适？**

| ID / 优先级 | 需求 | 验收标准 |
|---|---|---|
| F01 / P0 | 按主题、时间、预计难度和阅读状态筛选文章 | 显示主题来源（编辑/用户/AI）；无法估计时标未知；用户可手动更正阅读状态 |
| F02 / P0 | 根据显式兴趣、收藏和笔记主题生成推荐 | 每条显示一条可解释理由；用户可不感兴趣、稍后读、已读、减少此主题；纯查词不作为强兴趣信号 |
| F03 / P0 | 从已收录且用户未读的目录中找漏读 | 展示目录覆盖范围、更新时间、漏读时间窗与排序理由；只称“已收录目录中的未读文章” |
| F04 / P0 | 补背景、追后续、看不同角度三种推荐理由 | 关系可来自人工策展；AI 推断需标记；未读状态排除已读，重复条目合并 |
| F05 / P1 | 按用户最近阅读估计词汇负担与时间 | 展示为估计；查词不直接等于不会；无全文不计算生词比例；用户可选择更易/更难 |
| F06 / P1 | 新语境再遇见、主题时间线和语义去重 | 词汇匹配定位到新原句；已读或同文镜像不占“新文章”名额；旧文注明发表时间 |
| F07 / P2 | 观点拓展与跨领域探索 | 用户可调整探索比例；没有证据时不把文章自动贴为“反方” |

**P0 排序**：先过滤不可展示、重复、已读和明确不喜欢的内容，再按显式兴趣匹配、主题补充关系、时间适配排序；少量保留探索位。记录入选理由，避免首版依赖尚不存在的协同过滤数据。

**P1 排序提案**：归一化后使用 `0.35×兴趣匹配 + 0.20×主题补缺 + 0.20×阅读适配 + 0.15×词汇复现 + 0.10×内容多样性`，权重只作实验起点。没有全文时移除全文相关项、重归一化并显示推荐依据不足。时效性按主题调整，背景旧文不因发布时间久就一律降权。

**状态语义**：未开始、阅读中、已完成、暂不感兴趣分别记录；用户手动“已读”优先于系统进度推断。“读完”的自动建议可依据覆盖段落和活跃时长，但须允许纠正。冷启动用用户兴趣和人工策展，行为不足时不声称已经充分了解用户。

**供给不足**：少于可用数量时显示实际条数，并允许换主题或放宽日期；不能生成不存在的文章凑数。没有完整历史目录时不承诺找全所有漏文。首轮内测需准备至少 3 个主题、每主题 10 篇带来源的候选元数据，以及足够完成流程的可用正文；该数量是测试准备要求，不是现状。

## 9. AI、性能与可靠性要求

| 方面 | 首版要求 / 验收方式 |
|---|---|
| 引用 | 文本锚点由系统验证存在；质量样本逐条核对引用是否支持回答；存在引用不等于回答正确 |
| 并发选区 | 快速从词 A 切到词 B，晚返回的 A 结果不得覆盖 B；请求关联选区与版本 |
| 失败恢复 | AI 超时可重试或继续阅读；高亮和笔记不依赖 AI 成功；错误不清空输入 |
| 本地反馈 | 约定参考设备与网络后，选区菜单和高亮反馈 p95 ≤ 200ms；拼写判定 p95 ≤ 100ms |
| AI 响应 | 参考网络下解释首个有效内容 p95 ≤ 3s；超过 15s 给出明确重试状态；目标待实测 |
| 持久化 | 保存状态可见；重载恢复已保存数据；联网重试不重复创建词卡/笔记；导出含来源与标签 |
| 缓存 | 使用文章版本、选区、语言、生成任务等缓存；用户个性化与私人笔记隔离；更正后可失效重算 |
| 成本 | 记录每次任务耗时、用量、缓存命中和活跃用户成本；预算与限额可配置，耗尽后仍能阅读和练习 |
| 隐私 | 私人笔记默认私有；向 AI 提交的上下文范围可知；导出与删除账户数据有可验证结果 |
| 可访问性 | 键盘可到达主要操作，颜色不是唯一含义，焦点可见；移动端选区不被浮层挡住 |

首版支持预先加载正文的弱网阅读与待同步笔记；跨设备完整离线同步为 P1。同步冲突保留双方副本供处理，不静默覆盖用户内容。

## 10. 指标与学习效果验证

**北极星指标：每周完成有效学习闭环的用户数及占周活用户比例。** 有效闭环定义为：一篇文章标记完成且有活跃阅读记录，至少完成一次理解活动（笔记、理解题或带引用问答），并对该文至少 3 个词完成无提示拼写尝试。该指标衡量产品使用，不等于学习效果；用户未达阈值仍可正常阅读。

| 类别 | 指标与分母 | 用途 |
|---|---|---|
| 激活 | 首次会话完成阅读动作与首次拼写的用户 / 首次进入用户 | 检验上手门槛 |
| 持续使用 | 第 7 天返回用户 / 已满 7 天的新用户；每周闭环率 | 检验持续性 |
| 词汇保持 | 加入学习后第 7/30 天无提示首答正确词项 / 当次被测词项 | 同时报到期未测比例，避免只看留下来的用户 |
| 语境迁移 | 未见过且经人工核对的新句义项题正确数 / 有效题数 | 与原句记忆分开测量 |
| 阅读理解 | 难度相近新文章的理解题、复述评分及读时 | 避免只用查词次数下降推断能力提升 |
| 推荐质量 | 推荐后开始阅读率、有效读完率、漏读补读完成率、负反馈率 | 点击率不能单独决定推荐方向 |
| 体验护栏 | AI 引用错误率、翻译反馈、笔记丢失、延迟、成本 | 防止追求时长或频次伤害体验 |
| 笔记质量 | 每周回看/使用笔记人数、未解决问题被继续处理的比例、修改后采纳比例、签核耗时与积压量 | 访谈是否改变理解或后续行动；采纳率和笔记数量不单独等于学习效果 |

最小埋点：文章曝光/打开/状态修改、活跃阅读区间、选词/翻译、笔记保存、学习项加入、练习提交、提示/揭示、推荐理由及反馈、AI 失败与引用点击。分析默认记录 ID 和动作，不采集私人笔记全文或自由输入原文。

**首轮验证提案**：招募约 10–15 位目标用户完成一次任务观察，再开展 2–4 周小规模试用；数字是研究计划建议。记录基线阅读水平、兴趣与时间预算，访谈为何中断、为何选文、练习是否有负担。验证学习收益时比较“仅阅读辅助”与“阅读辅助 + 语境拼写复习”，控制总时间及材料难度，并进行延迟和新语境测试；样本不足只报告探索性结果。

暂不设没有基线支持的留存或提词量承诺。首次试用后再锁定量化增长目标；数据量达到要求前不把模型估计包装为测量结果。

## 11. 交付阶段与退出条件

| 阶段 | 交付物 | 进入下一阶段的条件 |
|---|---|---|
| 准备 | 可用正文与候选目录、3 个主题、关键界面原型、语境解释样本 | 内容路径可行；用户能理解四步主流程；样本来源完整 |
| MVP / P0 | 导入、阅读、查译、划线笔记、标签、带引用伴读、三种拼写、到期复习、基础漏读推荐与数据导出 | 所有 P0 验收通过；端到端闭环可用；隐私与来源不混淆 |
| 增强 / P1 | 更多导入、发音听写、论证导图、阅读挑战、主题页、自建/考试词库、适配推荐、学习报告 | 试用表明用户会持续读和复习；新增能力能解决观察到的问题 |
| 完整范围 / P2 | 3D 书页/Atlas、跨文综合、进阶个性化与探索 | 有需求证据、可用输入和质量验证；不拖累核心阅读 |

不在缺少团队规模、内容接入方式和技术约束时给出确定工期。建议先以单用户 Web 工作台做可用闭环，再决定账号体系、多端同步及服务规模；多人产品上线前必须补齐访问隔离与账户生命周期。

## 12. 首版发布检查清单

1. 用户可导入一篇文章，选词解释、选句翻译、高亮并保存笔记；刷新后能回到准确原句。
2. 同词不同义项可区分，同义项多来源不丢；三种首版练习可完成，提示、错误和独立成功记录正确。
3. 到期复习能按规则推进；原句回看不冒充无提示通过；原文临摹不冒充词汇掌握。
4. 至少一个完整主题可从当前文章找到有理由的未读候选；已读、负反馈和重复过滤生效；覆盖范围可见。
5. 问答在有证据、证据不足和请求超时三类场景行为正确；AI 解释与私人观点分开。
6. 原文更新、选区快速切换、弱网保存重试、导入错误和移动端输入法场景均无数据错位或丢失。
7. 抽取至少 30 个代表性单词/多义词/习语与 20 个长句做人工核对；引用不存在、用户数据串用、笔记丢失为发布阻断问题。样本量是首版检查下限，不构成统计质量保证。
8. 数据导出保留出处、标签、作者归属、候选版本与签核历史；AI 越权写个人库、未确认内容混入个人结论为发布阻断问题；逐条采纳、拒绝、撤回、重生成后的重审通过验收。
9. 删除测试账户后检查个人数据删除结果；性能和任务成本有实测记录。

## 13. 待确认事项与默认决策

| 待确认 | 当前默认 | 为什么影响产品 |
|---|---|---|
| 来源分工（已按用户补充确定） | Infinite Reader 管阅读，TypeWords 管拼写，知识库文章管笔记机制 | 三份来源均有正式能力映射 |
| 用户与难度 | B2 左右自学者优先，允许更广水平 | 决定辅助粒度与选文 |
| 平台 | 桌面 Web 优先，移动阅读可用 | 决定拼写与选区设计 |
| 内容供给 | 自带正文 + 可用目录，不假设拥有完整全文 | 决定阅读与漏读推荐上限，是最大外部依赖 |
| 是否首版必须包含全部视觉能力 | 按 P0/P1/P2 分期，全部在路线图保留 | 3D 与地图会显著扩大范围 |
| 是否直接复用现有工具源码 | 只迁移需求和交互思路 | 代码复用、许可与技术栈另行核验 |
| 商业模式、预算、团队与时间 | 暂不假设 | 评审后再形成排期和成本约束 |

这些问题不阻碍评审本 PRD，但内容供给必须在开发完整推荐前落实，优先级与范围须在承诺工期前锁定。
